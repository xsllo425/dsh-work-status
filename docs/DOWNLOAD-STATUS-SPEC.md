# 下载状态的读写契约

这张卡片只做一件事：把**本机下载器写下来的状态**读出来，画成一行进度。
它不下载、不取消、不修补数据——写方是下载器，读方是卡片，两边只通过一个文件说话。

这份文档就是那份契约。任何下载器按下面的约定写文件，卡片都能显示；不写，卡片就不画下载区，也不报错。

## 位置

```
<根目录>/jobs/<任务 id>/status.json
```

- `<根目录>` 默认是 `~/.agent-downloads`，可用环境变量 `AGENT_DL_HOME` 覆盖。
- `<任务 id>` 由下载器自己定，建议带上时间戳以便排序。
- 一个任务一个文件，**只写这一个文件**。卡片的缓存、去重、排序都基于它。

## 写入方式

必须**原子替换**：先写临时文件，再 `rename` 到 `status.json`。

卡片在读到半截文件时会静默跳过这一条（不会让整个面板崩掉），但那一刻那条进度就等于没显示出来。用 rename 可以根本避免这个窗口。

Windows 上 `rename` 可能返回 `EPERM`（杀毒软件或另一个句柄正开着目标文件），重试若干次即可。

## 字段

只认下面这些。多余字段会被忽略，不做校验也不报错。

| 字段 | 类型 | 必需 | 含义 |
| --- | --- | --- | --- |
| `status` | string | 是 | 任务总状态，见下表 |
| `phase` | string | 否 | 更细的当前阶段，见下表；缺省时按 `status` 显示 |
| `filename` | string | 否 | 显示用的文件名；缺省时卡片从 `url` 里猜 |
| `url` | string | 否 | 下载地址，只用来兜底显示名字和悬停提示 |
| `totalBytes` | number | 否 | 总大小，字节。有值才画百分比和进度条 |
| `receivedBytes` | number | 否 | 已收到，字节 |
| `speedBps` | number | 否 | 当前速度，字节/秒。为 0 时不显示速度，也不拿它算剩余时间 |
| `etaSeconds` | number | 否 | 预计剩余秒数。有就用，没有就按 `(totalBytes - receivedBytes) / speedBps` 现算 |
| `startedAt` | string | 否 | ISO 时间，任务开始。列表按它倒序 |
| `updatedAt` | string | 否 | ISO 时间，最后一次写盘。用来判断任务是不是断了 |
| `pid` | number | 否 | 干活的进程号。用来判断进程还在不在 |

### `status`

| 值 | 含义 |
| --- | --- |
| `probe` | 探测大小、看服务器支不支持续传 |
| `queued` | 排在别的任务后面 |
| `connecting` | 正在连 |
| `downloading` | 正在下 |
| `reconnecting` | 断了，正在重连 |
| `finalizing` | 校验、改名、落盘收尾 |
| `running` | 通用「在跑」，不知道具体阶段时用 |
| `done` | 完成 |
| `failed` | 失败 |
| `canceled` | 取消 |

前六项加 `running` 属于「应该还有进程活着」的活跃状态。`done` / `failed` / `canceled` 是终态，卡片不会再动它。

### `phase`

若写 `phase`，卡片显示为对应的中文阶段；遇到表里没有的 `phase`，退回显示 `running` 那一档，不会出现空白或原始英文。

## 中断怎么判定

活跃状态的任务，卡片会检查它是不是还在真跑：

- `updatedAt`（缺省用 `startedAt`）距今**不满 6 秒** → 一律当作在跑，不打扰；
- 满 6 秒且 `pid` 已不存在 → 标为中断（灰掉，写明「中断」）；
- 满 12 秒，即使 `pid` 还活着也标为中断——长时间不写盘的任务，宁可说断了。

所以下载器在下载空转（服务器不吐数据、等待重连）时也要**定期刷新 `updatedAt`**，否则会被误判成中断。频率 1 秒一次就够。

## 大小上限

卡片最多读最新 10 个任务，面板里最多同时列 4 行。旧任务的目录不必删，但也不会显示。

## 一句话版本

一个任务一个 `jobs/<id>/status.json`，原子替换，字段照上表写，活跃时每秒刷新 `updatedAt`。做到这些，卡片就能显示；做不到，最坏的结果只是那一行不出现。
